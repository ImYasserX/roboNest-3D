# RoboNest.3D

Bilingual (Iraqi Arabic / English) e‑commerce platform for **RoboNest.3D**, the 3D‑printing workshop of RoboNest. It sells made‑to‑order prints, customizable products, and downloadable 3D models, and accepts custom print jobs from customer files, with cash on delivery across Iraq.

- **Stack:** Next.js 16 (App Router, TypeScript), Tailwind CSS 4, next‑intl, Drizzle ORM, Zod.
- **Runtime:** Cloudflare Workers via OpenNext, with Cloudflare D1 (SQLite) and R2 (object storage).
- **Status:** built and verified locally. **Not deployed.** See [`FINAL_AUDIT.md`](FINAL_AUDIT.md) for what was verified and what must happen before launch.

## Requirements

- Node.js ≥ 20.18 (developed on Node 24) and npm
- No Cloudflare account is needed for local development: Wrangler runs D1 and R2 locally (Miniflare/workerd).

## Local development

```bash
npm install
npm run setup            # creates .dev.vars with a random APP_SECRET, applies D1 migrations locally
npm run db:seed          # sample catalog, 19 delivery zones, 2 admin accounts (passwords printed once)
npm run dev              # http://localhost:3000  → redirects to /ar (or /en by browser language)
```

- Storefront: `/ar`, `/en`. Admin: `/ar/admin`, `/en/admin`.
- The seed prints the passwords for `owner` (Super Admin) and `operations` (Operations). To choose them yourself, set `SEED_SUPER_ADMIN_PASSWORD` and `SEED_OPS_ADMIN_PASSWORD`. The Super Admin must enroll an authenticator app (TOTP) at first sign‑in.
- `npm run db:seed -- --reset` wipes local D1/R2 and reseeds. Seed products are clearly marked samples; their images are rendered from procedural 3D meshes, and the GLB previews and STL downloads use the same geometry. The seed creates no orders, customers, or reviews.
- Discount code for local testing: `WELCOME10`.

### Running the production bundle locally

```bash
npm run cf:build                               # next build + OpenNext → .open-next/
npx wrangler dev --port 8787 --ip 127.0.0.1    # runs the Worker in workerd with local D1/R2
```

Use `http://localhost:8787` (not 127.0.0.1): production cookies are `__Host-`/`Secure`, which browsers accept on `localhost` only.

## Environment

The project uses Cloudflare bindings and Worker variables. There is no `.env.example`: local values live in `.dev.vars` (generated by `npm run setup`, git‑ignored).

| Name | Kind | Required | Purpose |
|---|---|---|---|
| `DB` | D1 binding | yes | Primary database (`wrangler.jsonc`) |
| `MEDIA` | R2 binding | yes | Public catalog media (product images, GLB previews), served via `/media/*` |
| `PRIVATE_FILES` | R2 binding | yes | Digital products and customer uploads; never publicly addressable |
| `IMAGES` | Images binding | optional | Declared for OpenNext; not required by the custom image loader |
| `APP_SECRET` | **secret** | yes | ≥ 32 random chars. Encrypts admin TOTP secrets (AES‑GCM), derives order/request link tokens, hashes client IPs. `wrangler secret put APP_SECRET` in production. Rotating it invalidates enrolled TOTP (admins must re‑enroll) and existing order‑tracking links. |
| `SITE_URL` | var | yes | Public origin without trailing slash, e.g. `https://3d.robonest.iq`. Used for canonical URLs, sitemap, JSON‑LD, reset links. |
| `NEXT_PUBLIC_IMAGE_TRANSFORMS` | build‑time var | recommended | Set to `cloudflare` at build time to resize images through Cloudflare Image Transformations (`/cdn-cgi/image/…`). Unset: original images are served. Not a secret. |
| `SEED_*` | local only | no | Seed script inputs (`SEED_SUPER_ADMIN_PASSWORD`, `SEED_OPS_ADMIN_PASSWORD`, `SEED_WHATSAPP`, `SEED_SUPER_ADMIN_TOTP_SECRET` for automated tests only) |

Secrets never use the `NEXT_PUBLIC_` prefix and are only read in server code (`src/server/env.ts`).

## Database migrations

Schema: `src/server/db/schema.ts`. Migrations: `drizzle/migrations/`, applied by Wrangler.

```bash
# after changing schema.ts
npm run db:generate                 # drizzle-kit → new SQL migration file (review it!)
npm run db:migrate:local            # apply to local D1
npx wrangler d1 migrations apply robonest-3d --remote   # production (see deployment checklist)
```

Never change the production schema by hand. Every change goes through a reviewed migration file.

## Project layout

```
src/
  app/[locale]/(store)/   storefront pages (home, catalog, product, cart, checkout, account, content)
  app/[locale]/admin/     admin login + (panel) pages
  app/api/                uploads, downloads, admin uploads/files
  app/media/[...key]/     public media from R2
  components/             ui/ primitives, layout/, catalog/, product/, cart/, checkout/, order/, account/, custom/, admin/
  i18n/                   next-intl routing and request config
  lib/                    shared pure logic: pricing, order status, permissions, phone, money, search
  server/
    auth/                 crypto, password hashing, TOTP, sessions, request guards
    services/             business logic (framework-free, unit/integration tested)
    actions/              server actions (thin: validate → authorize → call a service)
    db/                   Drizzle schema and client
    storage/              upload validation and streaming
  middleware.ts           locale routing, CSP nonce, CSRF origin check, admin gate
messages/{ar,en}.json     all user-facing strings (1,064 keys each, parity-checked)
drizzle/migrations/       SQL migrations
scripts/                  setup, seed, i18n check
tests/                    unit + integration (Vitest)
e2e/                      Playwright
```
